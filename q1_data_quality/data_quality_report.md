# Q1.1 数据质量初探报告

本报告由 `q1_data_quality/q1_code.py` 基于全部原始记录生成。统计线索与业务结论分开；当前未删除、去重、补值、裁剪空格或改写任何原始 CSV。

## 1. 数据范围与统计口径

- 固定来源：`mashlyn/online-retail-ii-uci/versions/3`。
- SHA-256：`32569a66f3842a82b0d8c4d63b263c5d98a76bde5d1f65c6c01bf457e541d3a9`。
- 记录数：**1,067,371**；原始字段数：**8**。记录是明细行，不等于订单数。
- 时间范围：`2009-12-01T07:45:00` 至 `2011-12-09T12:50:00`，未擅自指定时区。
- CSV 最初全部按字符串读取。统计视图显式转换 Quantity、Price 和 InvoiceDate；ID 即使形似数字也保留文本。
- 缺失指原始空字段；空白字符单独检查，文字 NA 不自动视作缺失。类型转换失败另列，不与原始缺失混为一谈。
- 所有比例以全部明细行数为分母。数值统计保留负数、零和极端值；标准差为样本标准差（ddof=1）。
- 唯一值和 TOP 10 排除空值，按原始文本精确区分；频次并列按文本升序。引号内的尾部空格有意保留。
- 题目 InvoiceNo / UnitPrice 分别对应本文件 Invoice / Price。

## 5. 八项需要进一步核查的现象

### 5.1 客户标识缺失可能改变客户分析样本

缺少 Customer ID 的记录有 **243,007 条（22.7669%）**。这些记录无法直接归属到具体客户；如果先统一删掉，再做销售统计，统计范围也会随之改变。下一步需要比较其金额、国家和商品分布，当前不能直接把它们认定为游客订单。

### 5.2 描述缺失与零价格、客户缺失同时出现

Description 为空的记录有 **4,382 条（0.4105%）**；其中 **4,382** 条价格为零，**4,382** 条同时缺少客户 ID。这种共同出现的模式值得核查。是否为库存调整等业务，需结合描述、发票及更多上下文，不能仅据此定性。

### 5.3 存在八个原始字段完全一致的重复记录

按原始八字段逐项比较，重复组共涉及 **67,242** 条记录；每组保留第一条后，其余 **34,335 条（3.2168%）**。这不是“重复发票数”，因为一张发票本来就可能含多个商品明细。数据缺少独立行标识，现阶段不能区分重复导入与真实重复明细，故仅标记，不直接去重。

### 5.4 负数量和 C 前缀并非完全对应

负数量记录有 **22,950 条（2.1501%）**，C 前缀记录有 **19,494** 条。其中 **3,457** 条负数量记录没有 C 前缀；另有 **1** 条 C 前缀记录的数量非负。题面将 C 前缀作为取消记录线索，因此不能简单把“Quantity < 0”与“C 前缀”当作同一规则。

### 5.5 零价格与负价格需要不同的调查路径

Price 为零的记录有 **6,202 条（0.5811%）**；负价格记录有 **5 条（0.0005%）**。负价格中 **5** 条描述为 `Adjust bad debt`，为核查坏账调整提供了直接文本线索。不能将负价格一律归因于录入错误，也不能在没有业务定义时将零价格自动填成普通商品价格。

### 5.6 数量极值远离主体分布

Quantity 中位数为 **3**，P99 为 **100**，但范围达到 **-80,995 至 80,995**。正负极值的原始证据见下方；需检查客户、商品及发生时间是否对应，不能仅凭统计距离删除。

### 5.7 最高价格未必是普通商品单价

Price 中位数为 **2.1**，P99 为 **18**，最高却为 **38,970**。下方最高价格记录展示其业务代码、描述与数量。计算商品价格分布前需要先确认该类记录是否属于商品销售。

### 5.8 发票号与业务代码不能统一转换成数字

非纯数字 Invoice 有 **19,500 条（1.8269%）**。不符合“数字主体加可选字母后缀”格式的 StockCode 有 **6,094 条（0.5709%）**。这只是格式筛选，并不证明这些代码都是非商品；自动转数值会丢失业务信息。
